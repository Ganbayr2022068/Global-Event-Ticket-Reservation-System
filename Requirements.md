# **Global Event Ticket Reservation System**

## 1\. Product Vision

This product aims to help people who want to buy event tickets easily and reserve available seats quickly. These events can include concerts, sports, festivals, and other activities.

## 2\. Users and Stakeholders

### **Users**

* Customers  
* Event organizers  
* System administrators

### **Stakeholders**

* Customers who buy tickets  
* Event organizers  
* Event companies  
* Venue owners  
* Payment companies  
* System administrators

## 3\. Personas

### Persona 1

**Name:** Namuun  
**Age:** 20   
**Occupation:** University Student

Namuuna likes concerts and festivals. She sometimes travels to different countries and wants to find events online.

**Goals:**

* Find interesting events  
* Check ticket prices  
* Reserve tickets online  
* Get a digital ticket

**Problems:**

* Some ticket websites are difficult to use.  
* It can be difficult to find events in other countries.

### Persona 2

**Name:** Han  
**Age:** 32  
**Occupation:** Event Organizer

Han organizes concerts and small events. She needs a system to add her events and manage tickets.

**Goals:**

* Add new events  
* Set ticket prices  
* Check how many tickets are sold  
* Manage events

**Problems:**

* Managing tickets manually takes a lot of time.  
* It is difficult to know how many tickets are left.

### Persona 3

**Name:** Michael  
**Age:** 30  
**Occupation:** System Administrator

Michael is responsible for managing the ticket reservation system.

**Goals:**

* Manage users  
* Manage events  
* Check the system  
* Keep the system safe

**Problems:**

* Some users may create fake accounts.  
* Popular events can have many users at the same time.

## 4\. Scenarios

2. ### She searches for a concert.

3. ### She chooses an event.

4. ### She checks the event information.

5. ### She chooses a ticket.

6. ### She makes a payment.

7. ### The system confirms the reservation.

### Sarah wants to add a new concert.

1. ### Han logs into her organizer account.

2. ### He clicks "Add Event".

3. ### He enters the event name and information.

4. ### He adds the ticket price and number of tickets.

5. ### He submits the event.

6. ### The administrator checks the event.

7. ### The event is published on the website.

## **Scenario 3 – Canceling a Ticket**

A customer wants to cancel a ticket.

1. The customer logs into the system.  
2. The customer opens "My Tickets".  
3. The customer chooses a ticket.  
4. The customer clicks "Cancel".  
5. The system checks if cancellation is possible.  
6. The system cancels the ticket.  
7. The ticket becomes available again.

## 7\. Acceptance Criteria

**AC-01:** The user can create an account using valid information.

**AC-02:** The user can log in using the correct email and password.

**AC-03:** The system shows events when the user searches for an event.

**AC-04:** The user can filter events by location and price.

**AC-05:** The system shows the event name, date, location, and ticket price.

**AC-06:** The user can only choose tickets that are available.

**AC-07:** The system confirms the reservation after successful payment.

**AC-08:** The user receives a digital ticket after buying a ticket.

**AC-09:** The user can see their reservations.

**AC-10:** The user can cancel a ticket when cancellation is allowed.

**AC-11:** Organizers can add new events.

**AC-12:** Organizers can change ticket information.

**AC-13:** Organizers can see sold and available tickets.

**AC-14:** Administrators can manage users.

**AC-15:** Administrators can approve or reject events.

## 8\. Functional Requirements

**FR-01:** The system shall allow users to create an account.

**FR-02:** The system shall allow users to log in and log out.

**FR-03:** The system shall allow users to search for events.

**FR-04:** The system shall allow users to filter events by location and price.

**FR-05:** The system shall show event information.

**FR-06:** The system shall show available tickets.

**FR-07:** The system shall allow users to select tickets.

**FR-08:** The system shall allow users to make online payments.

**FR-09:** The system shall create a digital ticket after successful payment.

**FR-10:** The system shall show users their reservations.

**FR-11:** The system shall allow users to cancel tickets when possible.

**FR-12:** The system shall allow organizers to add events.

**FR-13:** The system shall allow organizers to edit their events.

**FR-14:** The system shall show ticket sales information to organizers.

**FR-15:** The system shall allow administrators to manage users and events.

## 9\. Non-functional Requirements

**NFR-01 – Performance:** The website should load pages quickly.

**NFR-02 – Security:** User account and payment information should be protected.

**NFR-03 – Usability:** The website should be easy to understand and use.

**NFR-04 – Reliability:** The system should work correctly when users reserve tickets.

**NFR-05 – Availability:** The website should be available most of the time.

**NFR-06 – Compatibility:** The website should work on computers, tablets, and mobile phones.

**NFR-07 – Scalability:** The system should be able to handle many users at the same time.

**NFR-08 – Maintainability:** The system should be easy to update and fix.
